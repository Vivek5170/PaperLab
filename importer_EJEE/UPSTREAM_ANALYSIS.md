# Upstream extractor analysis

Reference repository: https://github.com/Vivek5170/PaperLab

Downloaded commit: `765b4d76201bba010ede1c573d7a0f3186311b01`. The reference checkout is unchanged.

## How Node 2 runs

`graph.py` implements the ReAct loop: construct `get_llm().bind_tools(..., parallel_tool_calls=False)`, invoke with retries, append the AI response, log token usage, execute requested tools, then append their results. Image tools return a LangGraph `Command` containing a text ToolMessage followed by an image-bearing HumanMessage. This image channel is required by the configured provider; putting images directly in ToolMessages is deliberately avoided.

The normal `extractor_app` first prepares cleaned/split PDFs and initializes question/solution boundaries from `papers`. The model then scans physics pages, submits question and solution files, and completion is checked against on-disk coverage. That indexing/cleaning path is unnecessary for EJEE's already-mapped image parts. The importer implements the same agent-turn pattern per known question, using the original native tools and restricting the available pages.

## Bound tools

| Tool | Native behavior | Importer use |
|---|---|---|
| `get_page_image` | Render PDF page; return image in HumanMessage | Same implementation, allowed pages only; initial images already supplied |
| `assisted_crop` | Guess box at 0–1000 scale; snap embedded image or adjust vector/plain crop; show preview and edge feedback | Same implementation on lossless image PDFs; raster bodies usually use plain mode |
| `exact_crop` | Manual box refinement after three assisted attempts on the same figure name | Same implementation and retry gate |
| `submit_question` | Validate qtype, figure references/side, braces/environments; normalize options/backticks/underscores; write TeX and native question row | Same implementation, fixed identity |
| `submit_solution` | Check mapped question exists; preserve answer-first layout; normalize steps; validate syntax and figure references; write solution or explicit missing placeholder | Same implementation; importer rejects placeholders when mapped solution images exist |
| `get_page_text` | Cheap text-layer reads, mainly for key sheets | Not bound: synthetic image canvases have no text layer or common key sheet |

`verify_latex_syntax` is called internally by submissions, not bound to the agent. Despite the docstring saying “compile-check”, the inspected submission implementation checks braces/environments and references; it does not actually run a full TeX compiler. A successful save alone is not evidence of perfect visual transcription or rendered layout.

Crop attempts are tracked per paper/question/filename; filenames must remain stable. The crop standard requires full labels, arrows, components and axes, exclusion of foreign text, and a small clear margin. `assisted_crop` first, then `exact_crop` only after three unsuccessful assisted attempts. Embedded-image snapping can incorrectly return a whole raster body if the guessed box overlaps most of it, so previews must be inspected. We do not treat source body bounds as diagram bounds.

## Prompt rules retained

The full `prompts/extractor_prompt.md` is loaded verbatim at runtime. The appended importer adapter overrides only document-wide assumptions: fixed mapped pages/identity, no indexing, no shared answer sheet, no mandatory numeric exam category for subjective textbook questions, and no invented answer when a printed solution has no explicit conclusion. Strict wording/symbol/unit/option transcription, complete solution paragraphs, unreadable flags, figure standards, correction loops and side separation remain in effect.

The source prompt itself contains a tension: its general strict-transcription rule prohibits silently correcting content, while a later note encourages physics-based interpretation of ambiguous glyphs. The adapter reinforces unreadable flags rather than invention. Human review is still necessary for ambiguous source images.

## Storage and statistics

Native output: `Outputs/{paper_id}/{question_number}/question.tex`, `solution.tex`, `figures/qfigN.png` and `sfigN.png`. Paper metadata uses the chapter as `paper_name`, exact textbook name as `source_institute`, `exam_type=Textbook`, and no fabricated paper date. Image-PDF paths and boundaries are real. `pdf_hash` comes from native registration. `questions.latex_folder` points to the actual run output.

PaperLab has no separate denormalized statistics tables: `token_usage` is the accounting ledger, while paper/question/topic totals are calculated from native rows and files. The importer logs only real fresh extraction calls; upstream Node 3 logs its own calls. Indexer usage remains absent because indexing was skipped. Crop mode sidecars are generated by native tools. Original student/exam scoring tables are unrelated to extraction usage and are not imported.

## Node 3 must be fresh

`run_topics.classify_question` reads the new `question.tex` + `solution.tex` and upstream's numbered topic reference, invokes the original topic prompt, parses topics/difficulty/suggestion and writes native auto links and token usage. The importer invokes that exact function. EJEE node IDs, tags and difficulty are retained solely in provenance and are never seeded into target classification.
